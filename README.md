# 每日签到面板

跑在 Cloudflare Workers 上的每日自动签到面板：**网页后台管账号 + D1 存数据 + 定时自动签到 + 推送通知**。
零依赖，一个 Worker 搞定；带一个配套的浏览器扩展（用来抓 Cookie、以及在你的网络里代为发请求）。

## 它是什么

一句话：**把你每天要手动点的那些「签到」，交给 Cloudflare 每天自动点一遍，并用通知告诉你结果。**

能做什么：

| 能力 | 说明 |
|---|---|
| 多账号管理 | 增删改、启用/停用、单个或全部手动执行 |
| 定时自动签到 | 每天指定时间自动跑（可精确到分钟），支持时区，每个账号还能设自己的时间 |
| 扩展取 Cookie | 一键把当前网站的 Cookie + 浏览器 UA 传回面板，自动建号并试跑 |
| 本地网络执行 | 扩展代发 HTTP 请求，用你家的 IP + 你的 Cookie，绕过 Cloudflare 机房 IP 被拦的问题 |
| 万能「自定义 HTTP」 | 抓一次 cURL 就能接入任意网站，支持多步（先登录拿 token 再签到） |
| 自动探测签到接口 | 给个网址，面板帮你找候选签到接口 |
| 运行日志 | 每次结果、耗时、网站原始回馈，保留最近 500 条 |
| 推送通知 | Telegram / Bark / 通用 Webhook 推签到日报 |

> 一句话理解架构：**Cloudflare 负责「什么时候跑、跑哪个账号、怎么判成功」，扩展负责「用你的网络和 Cookie 把请求发出去」。**

## 部署到 Cloudflare（详细步骤）

### 0. 准备

- 一个 Cloudflare 账号（免费版就够）
- 本机装好 **Node.js 18 或更高版本**（命令行输入 `node -v` 能看到版本号）
- 会用命令行，能复制粘贴命令即可

> 下面所有 `npx wrangler` 命令建议加 `@latest`（写成 `npx wrangler@latest`），
> 老版本 wrangler 不支持本项目用到的静态资源（assets）配置。

### 1. 登录 Cloudflare

```bash
npx wrangler@latest login
```

浏览器会弹出授权页，点同意即可。看到 `Successfully logged in` 就算好了。

### 2. 创建 D1 数据库

```bash
npx wrangler@latest d1 create daily-checkin-panel
```

命令会输出一段配置，**重点记住那行 `database_id`**，像这样：

```
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

### 3. 把 database_id 填进 `wrangler.toml`

打开项目根目录的 `wrangler.toml`，找到最后一段：

```toml
[[d1_databases]]
binding = "DB"
database_name = "daily-checkin-panel"
database_id = "23a3455d-69d7-49ec-a71f-4440dff9957c"
```

**把 `database_id` 换成第 2 步你自己的那一串**（仓库里这行是原作者的值，不改会连不上你自己的库）。

> `binding = "DB"` 不用改，代码里就是按这个名字取数据库的。

### 4.（可选，但推荐）设置加密密钥

账号密码/Cookie 会加密后存进 D1。默认第一次运行时自动生成密钥并存在 D1；
如果你希望「即使重建数据库也不丢密钥」，用固定密钥：

```bash
# 生成一个 32 字节随机密钥
openssl rand -base64 32
```

把输出的字符串交给下面这条命令（会提示你粘贴）：

```bash
npx wrangler@latest secret put ENCRYPT_KEY
```

> Windows 没有 `openssl` 的话，可以在面板里随便用一个足够长的随机字符串，或直接用默认的自动生成。

### 5. 部署

```bash
npx wrangler@latest deploy
```

成功后会输出你的网址，形如 `https://daily-checkin-panel.你的账号.workers.dev`。

### 6. 打开面板，初始化

用浏览器打开上面的网址 → **设置管理密码**（至少 6 位）→ 进入后台。

数据库表会在第一次访问时**自动创建**，不需要你手动建表。

### 7. 绑定自定义域名（强烈建议）

`*.workers.dev` 域名在国内访问经常不稳定，会导致：

- 你自己打开面板慢或打不开
- **扩展连不上面板**，于是「本地网络执行」全部变成跳过

做法：Cloudflare 控制台 → **Workers 和 Pages** → 选中你的 Worker → **设置 / 域和路由** →
添加 **自定义域**（域名需托管在 Cloudflare）。之后再访问你自己的域名即可。

### 8. 本地预览（可选）

```bash
npx wrangler@latest dev
```

会用本地模拟的 D1 起一个开发服务器，用来改代码试效果，不影响线上数据。

## 使用说明

按顺序做一遍就通了。

### 第 1 步：拿到「扩展用 API Key」

面板 → **设置** → 找到「扩展用 API Key」→ 生成 / 复制一串 Key。

> 这个 Key 是扩展调用面板接口的凭证，**不要发给别人**。它不会写进扩展的下载包里，
> 需要你自己复制粘贴到扩展里（这样即使扩展包泄露，别人也拿不到你的面板权限）。

### 第 2 步：装扩展

见下一节 [浏览器扩展怎么装](#浏览器扩展怎么装)。

### 第 3 步：把面板地址和 Key 填进扩展

点浏览器工具栏上的扩展图标：

- **签到面板地址**：默认已经自动带出（下载扩展时面板地址被注入了）；没带出就手填 `https://你的域名`
- **API Key**：粘贴第 1 步复制的那串

点 **🔌 面板连接检查**，显示「连接正常 ✅ API Key 有效」就 OK。

### 第 4 步：登录要签到的网站，抓 Cookie

以 NodeSeek 为例：

1. 浏览器打开 www.nodeseek.com 并**手动登录**（有人机验证也没关系，你手点一下就好）
2. 保持在该网站的页面上，点扩展图标
3. 点 **一键发送到签到面板**
4. 面板会自己打开，**自动匹配站点 → 自动建号 → 自动试跑一次**，并弹出结果

其它取 Cookie 的方式见 [Cookie 怎么拿](#cookie-怎么拿)。

### 第 5 步：看结果

面板 → **账号** 列表：

- **状态列**显示 ✅ / ❌ / ⏭️（跳过）
- **回馈列**显示网站真实返回的原文，例如「签到成功：获得 5 个鸡腿」
- 想看细节去 **日志** 页，有完整回馈、耗时、以及是否走了本地网络

### 第 6 步：设置每天几点跑

面板 → **设置** → 选时间（可精确到分钟）和时区 → 保存。**不用重新部署。**

每个账号还可以在账号列表单独设自己的时间（留空 = 跟随全局）。

## 浏览器扩展怎么装

扩展包由面板动态生成，**面板地址会自动注入**进去。

1. 打开面板 → 找到「下载扩展」入口，或在地址栏直接访问：

   ```
   https://你的域名/cookie-plugin-2.2.zip
   ```

   浏览器会下载一个 zip。

2. **解压**这个 zip 到一个固定文件夹（比如 `D:\cookie插件`）。
   ⚠️ 解压后**不要删除、不要移动**，浏览器会一直读这个目录。

3. 打开扩展管理页：
   - Chrome：地址栏输入 `chrome://extensions`
   - Edge：地址栏输入 `edge://extensions`

4. 打开右上角的 **开发者模式**（Developer mode）。

5. 点 **加载已解压的扩展程序**，选择第 2 步解压出来的文件夹（**选中文件夹本身**，不是里面的某个文件）。

6. 工具栏出现 🍪 图标即安装成功。点它 → 填 API Key → 点「面板连接检查」验证。

> ⚠️ 面板换了域名（比如从 workers.dev 换到自定义域名）后，需要在扩展弹窗里把**面板地址改一下**。

扩展弹窗上的四个按钮：

| 按钮 | 作用 |
|---|---|
| 一键发送到签到面板 | 把当前网页的 Cookie + UA 发给面板，自动建号并试跑 |
| 一键复制全部信息（含 UA） | 复制成一段 JSON，粘到面板「粘贴扩展内容」里也行（不想让面板自动打开时用） |
| 立即执行待办签到 | 让扩展马上领一次任务并执行 |
| 面板连接检查 | 验证地址和 Key 是否正确 |

## Cookie 怎么拿

按推荐顺序：

| 方式 | 怎么做 | 适用 |
|---|---|---|
| **扩展一键发送**（推荐） | 登录网站 → 点扩展 → 一键发送 | 全部站点；能拿到 HttpOnly Cookie |
| 粘贴请求头文本 | F12 → 网络 → 点任意请求 → 复制 `Cookie:` 那一行 → 粘到面板 | 电脑上手动抓 |
| 复制为 cURL | F12 → 网络 → 右键请求 → 复制为 cURL → 面板「从 cURL 导入」 | 还能顺便带入 UA、参数 |
| Cookie-Editor 导出 JSON | 用 Cookie-Editor 插件导出，粘到面板 | 已有该插件的用户 |
| 手机抓包（ProxyPin 等） | 抓包 App 导出 Cookie | 手机端签到（如夸克网盘） |

**小贴士**：

- 有些站点（吾爱破解）要求 **Cookie 与 User-Agent 配对**，UA 不一致会被 WAF 拦。扩展会自动把浏览器 UA 一起带回来。
- Cookie 会过期。到期后面板日志会提示「登录已失效」，重新抓一次即可（1 分钟）。

## 执行模式：云端 / 本地网络

面板账号列表会显示一个模式徽章：

| 徽章 | 含义 |
|---|---|
| ☁️ 云端 | Cloudflare 机房的 IP 直接发请求。适合普通 API 类站点 |
| 🌐 本地网络 | 请求**经由你的浏览器扩展**发出，用你家的 IP + 你的 Cookie。适合会拦机房 IP 的站点 |

- 扩展**在线**时，站点默认走本地网络；扩展**离线**时，需要本地网络的账号会被记为 **⏭️ 跳过**（不是失败，也不会覆盖上一次的真实结果）。
- 扩展是否在线，Panel 判断依据是「最近 90 秒内有没有轮询过面板」。
- 可以在账号上手动切换：跟随默认 → 本地网络 → 云端 循环。

> 为什么要本地网络：Cloudflare 的出口 IP 常被论坛/WAF 直接拒绝（返回验证页），
> 用你家的 IP 就和平常用浏览器一样。

## 定时签到怎么设

`wrangler.toml` 里写的是：

```toml
[triggers]
crons = ["* * * * *"]
```

意思是 **Cloudflare 每分钟叫醒一次 Worker**，但 Worker 内部会比对「你设置的签到时间」
（小时 + 分钟），**只有到点、且这个时刻还没跑过，才真的执行**，所以不会重复签到。

- 为什么是每分钟而不是每小时：因为面板支持 `08:30` 这种**分钟级**时间，每小时触发的话分钟就无效了。
- 要改签到时间：在**面板 → 设置**里改，**不用重新部署**。
- 时区也是在这里改（默认 `Asia/Shanghai`）。Cloudflare 的 Cron 本身走 UTC，换算交给 Worker。
- 每个账号可以用自己的时间：账号列表里单独设置，留空就跟随全局。

## 常见问题 FAQ

**Q：执行结果一直是 ⏭️ 跳过？**
A：说明这个账号需要「本地网络」，但扩展不在线。检查（1）扩展是否装着且启用；（2）扩展里的面板地址对不对（点「面板连接检查」）；（3）面板地址国内能不能打开——`*.workers.dev` 不稳定时请绑自定义域名。

**Q：日志说「遇到安全验证（WAF）」？**
A：站点识别到你不是正常浏览器。用浏览器打开该站点，手动过一次验证并登录，然后重新用扩展「一键发送」更新 Cookie 和 UA。

**Q：日志说「遇到人机验证」？**
A：站点的验证码/滑块**无法自动过**（这是所有签到脚本的通病）。人工在浏览器里登录一次，再用扩展重新抓 Cookie 即可。

**Q：日志说「登录已失效」？**
A：Cookie 过期，重新抓一次。多数站点 Cookie 有效期几天到几周。

**Q：想加一个没有内置的网站？**
A：用「自定义 HTTP」：浏览器里人工登录并手动签到一次 → F12 → 网络 → 找到签到请求 → 右键「复制为 cURL」→ 面板粘贴导入 → 填「响应应包含」关键词 → 保存试跑。多步流程（先登录拿 token）用「多步录制」。

**Q：更新面板代码会丢账号吗？**
A：不会。代码更新只替换 Worker 脚本，D1 数据库是独立的；表结构变更走版本化迁移（缺列自动补，不重建表）。

**Q：D1 免费额度够吗？**
A：个人使用完全够。本项目每分钟一次 Cron 唤醒，但绝大多数次数只是比对时间后立即返回，不做数据库写入。

## 数据与安全

- **管理密码**：PBKDF2-SHA256（10 万次迭代）哈希后存 D1，不存明文。
- **账号凭据**（Cookie / 密码 / token）：AES-GCM 加密后存 D1；密钥来自 `ENCRYPT_KEY` Secret 或首次运行自动生成。
- **会话**：服务端 session + HttpOnly + Secure + SameSite Cookie，7 天过期。
- **扩展接口**：使用单独的「扩展用 API Key」鉴权；服务端已支持对扩展请求做 **HMAC 签名校验 + 防重放**（默认不强制，兼容旧版扩展）。
- **推送密钥**：设置页读取时脱敏，更新时留空即保留旧值。
- **Cookie 传输**：扩展「一键发送」通过面板页面地址传回，面板读到后立即用 `history.replaceState` 清掉地址栏里的参数。

## 更新与备份

更新面板：

```bash
npx wrangler@latest deploy
```

备份数据库（建议偶尔做一次）：

```bash
npx wrangler@latest d1 export daily-checkin-panel --remote --output backup.sql
```

> 备份文件里含加密后的凭据；`ENCRYPT_KEY` 若是自动生成的，恢复时请用同一个 D1，否则凭据无法解密。

## 项目结构

```
daily-checkin-panel/
├── wrangler.toml          # Worker 配置、Cron、D1 绑定
├── src/
│   ├── index.js           # 路由 + API + Cron 入口
│   ├── runner.js          # 执行引擎（遍历账号 / 写日志 / 推送）
│   ├── db.js              # 表结构 + 版本化迁移
│   ├── crypto.js          # 密码哈希 / 凭据加解密
│   ├── schedule.js        # 签到时间与时区判定
│   ├── notify.js          # Telegram / Bark / Webhook
│   ├── probe.js           # 签到接口自动探测
│   ├── ext-zip.js         # 动态生成扩展 zip（注入面板地址）
│   ├── ext-files.js       # 自动生成：扩展源码内嵌
│   ├── lib/
│   │   ├── web.js         # 模拟浏览器的请求工具（UA/Referer/表单）
│   │   ├── relay.js       # 本地网络中继（Worker 侧）
│   │   ├── signals.js     # 统一网站反馈识别（成功/已签/登录/验证码/WAF）
│   │   └── ext-auth.js    # 扩展请求鉴权（API Key + 签名 + 防重放）
│   └── sites/             # 各站点签到模块 + index.js 注册表
├── public/
│   ├── index.html         # 管理后台 SPA
│   └── ext-src/           # 扩展源文件（改完需重新生成 ext-files.js）
├── tools/gen-ext-files.mjs
└── README.md
```

### 自己加一个站点

1. 在 `src/sites/` 新建文件（照着 `nodeseek.js` 抄最省事），导出：

```js
export const mysite = {
  id: 'mysite',
  name: '我的站点',
  desc: '一句话说明',
  fields: [{ key: 'cookie', label: 'Cookie', type: 'textarea', required: true }],
  tips: '给用户的提示',
  async run(creds, ctx) {
    // ctx: { env, db, account, meta }；meta 可读写并会自动持久化
    return { ok: true, message: '签到成功' };
  },
};
```

2. 在 `src/sites/index.js` 的 `SITES` 里注册。
3. 重新部署，网页表单会自动出现这个站点。

> 改完扩展源码（`public/ext-src/`）后，记得跑 `node tools/gen-ext-files.mjs` 重新生成内嵌文件，否则用户下载到的还是旧版扩展。
