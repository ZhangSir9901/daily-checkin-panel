# 每日签到面板

跑在 Cloudflare Workers 上的自动签到面板：**网页后台管账号 + D1 存数据 + 每天定时自动签到 + 推送通知**。
零依赖，一个 Worker 搞定，另配一个浏览器扩展（负责抓 Cookie，以及用你家的网络代发请求）。

> 本项目只需要 **Cloudflare 免费账号**，不需要买服务器、不需要 Cloudflare 的 API Token。

---

## 先看这里：3 个最容易踩的坑

| 坑 | 后果 | 怎么办 |
|---|---|---|
| `wrangler.toml` 里的 `database_id` 没换成自己的 | Worker 连不上数据库，面板打不开/报错 | 见 [第 3 步](#第-3-步创建-d1-数据库并把-id-填进去) |
| 又把 `EXTERNAL_API_KEY` 设成 Worker Secret | 它的优先级**高于**面板里生成的那串 Key，会出现「面板里复制了 Key，扩展却连不上」 | **不要设置它**，见 [第 4 步](#第-4-步可选但强烈建议设置加密密钥) 的注意事项 |
| 面板换了网址（或更新了版本）后没管扩展 | 扩展还在连旧地址 / 还是旧代码 | 换域名后去扩展弹窗改「签到面板地址」；面板更新后**重新下载并重新加载一次扩展** |

## 它是什么

一句话：**把你每天要手动点的那些「签到」，交给 Cloudflare 每天自动点一遍，并把结果通知你。**

| 能力 | 说明 |
|---|---|
| 多账号管理 | 增删改、启用/停用、单个或全部手动执行 |
| 定时自动签到 | 每天指定时间自动跑（精确到分钟），支持时区，每个账号还能设自己的时间 |
| 一键加账号 | 扩展「一键复制全部信息」→ 面板粘贴 → 自动认站点、自动填 Cookie 和 UA、自动试跑 |
| 本地网络执行 | 扩展代发 HTTP 请求，用你家的 IP + 你的 Cookie，绕过机房 IP 被拦的问题 |
| 万能「自定义 HTTP」 | 抓一次 cURL 就能接入任意网站，支持多步（先登录拿 token 再签到） |
| 自动探测签到接口 | 给个网址，面板帮你找候选签到接口 |
| 运行日志 | 每次结果、耗时、网站原始回馈，保留最近 500 条 |
| 推送通知 | Telegram / Bark / 通用 Webhook 推签到日报 |

> 架构一句话：**Cloudflare 负责「什么时候跑、跑哪个账号、怎么判成功」，扩展负责「用你的网络和 Cookie 把请求发出去」。**

## 部署：照着做一遍就能用

### 第 1 步：注册 Cloudflare + 装 Node.js

1. 打开 <https://dash.cloudflare.com/sign-up> 注册一个免费账号（只要邮箱 + 密码，不用绑卡）。
2. 装 **Node.js 18 或更高版本**：<https://nodejs.org/> 下载 LTS 版一路下一步。
3. 验证：打开命令行（Windows 按 `Win+R` 输入 `cmd` 回车；Mac 打开「终端」），输入：

   ```bash
   node -v
   ```

   能打印出 `v18.x` / `v20.x` / `v22.x` 之类就 OK。**看不到版本号说明没装好，先解决这个再往下。**

### 第 2 步：登录 wrangler

wrangler 是 Cloudflare 的官方命令行工具，用 `npx` 免安装直接跑（第一次会自动下载，等十几秒）。

```bash
npx wrangler@latest login
```

浏览器会弹出一个授权页，点 **Allow / 同意**。命令行出现 `Successfully logged in` 就成功了。

> 所有命令都建议写成 `npx wrangler@latest`。**不要**直接写 `wrangler`，老版本不支持本项目的静态资源（assets）配置。

### 第 3 步：创建 D1 数据库，并把 id 填进去

D1 是 Cloudflare 的免费 SQLite 数据库，账号和 Cookie 都存在这里。

**3.1 在项目目录里执行**（先 `cd` 到你解压出来的那个文件夹）：

```bash
npx wrangler@latest d1 create daily-checkin-panel
```

输出大概长这样，注意最后那行 `database_id`：

```
✅ Successfully created DB 'daily-checkin-panel' in region WEUR
Created your new D1 database.

[[d1_databases]]
binding = "DB"
database_name = "daily-checkin-panel"
database_id = "1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d"
```

**3.2 复制那串 `database_id`，打开项目根目录的 `wrangler.toml`，替换掉这一行：**

```toml
[[d1_databases]]
binding = "DB"
database_name = "daily-checkin-panel"
database_id = "把这里换成你自己的那一串"
```

- `database_name`：就是上面命令里用的名字 `daily-checkin-panel`。你想换个名字也行，但**两次要一致**（`d1 create` 用的名字 = 这里填的名字）。
- `binding = "DB"`：**不要改**，代码里就是按这个名字取数据库的。
- 仓库里自带的 `database_id` 是作者自己的库，**不改就连不上**。

> 命令报错 `database with name ... already exists`？说明你之前建过。执行下面这条查 id，填进 `wrangler.toml` 即可：
>
> ```bash
> npx wrangler@latest d1 list
> ```

**3.3 表结构不用手动建。** 第一次打开面板时会自动建表，以后升级代码也会自动加列（不删你的数据）。

### 第 4 步（可选但强烈建议）：设置加密密钥

账号里的 Cookie、密码、token 都是加密后存进 D1 的，密钥叫 `ENCRYPT_KEY`。

- **不设置也能用**：首次运行会自动生成一把密钥并存在 D1 里。
- **但建议固定下来**，否则哪天你重建了 D1，旧数据就解不开了。

**4.1 生成一把 32 字节的密钥**（任选一条命令，效果一样）：

```bash
# 有 Node.js 就能用，Windows / Mac 通用
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

```bash
# Mac / Linux 用 openssl 也行
openssl rand -base64 32
```

会得到类似 `Xq7l0nJm8vP2sT4uW6yA1bC3dE5fG7hI9jK0lM2nO4=` 的一串。

**4.2 把它写进 Worker Secret：**

```bash
npx wrangler@latest secret put ENCRYPT_KEY
```

会提示 `Enter a secret value:`，把上面那串粘进去回车（粘贴时屏幕不显示，正常现象）。

> ⚠️ 必须是**正好 32 字节的 base64**。如果面板报错 `ENCRYPT_KEY 必须是 32 字节的 base64 字符串`，说明长度不对，重新用上面的命令生成。

> ⚠️ **不要把 `EXTERNAL_API_KEY` 设成 Secret。**
> 面板里的「扩展用 API Key」默认存在 D1（在面板上生成、随时可换）。而环境变量里的 `EXTERNAL_API_KEY` **优先级更高**，一旦设了，就会盖掉面板里那串 —— 表现就是「面板里复制了 Key，扩展却一直连不上 / 报 API Key 无效」。
> 只有一种情况才需要它：你想把 Key 固定成环境变量、不让人在面板上改。那就把它设成和面板里显示的一模一样。

### 第 5 步：部署

```bash
npx wrangler@latest deploy
```

成功后会打印你的网址，形如：

```
https://daily-checkin-panel.你的账号名.workers.dev
```

这个地址就是你的**签到面板**。`wrangler.toml` 里的定时触发器（每分钟唤醒一次）也会在这步一起生效，不用去控制台设置。

### 第 6 步：打开面板、设置管理密码

浏览器打开上面那个网址 → 输入并确认**管理密码**（至少 6 位）→ 进入后台。

- 密码用 PBKDF2-SHA256 加盐哈希后存 D1，不存明文。
- 忘了密码：页面上没法找回。清掉 D1 里的 `admin_hash` 就能重新走一次「设置管理密码」：

  ```bash
  npx wrangler@latest d1 execute daily-checkin-panel --remote --command "DELETE FROM settings WHERE key='admin_hash'"
  ```

  建议平时把密码记在密码管理器里。

### 第 7 步：生成扩展用的 API Key

面板 → **设置** → 找到「🔌 浏览器扩展」→ 点 **🎲 生成** → 再点 **📋 复制**。

这串 Key 是扩展调用面板接口的凭证：

- 它**不会**被写进扩展的下载包里，需要你手动粘到扩展弹窗里（这样扩展包就算被别人拿到，也连不上你的面板）。
- 泄露了就回来点「生成」换一把，然后在扩展里更新。

### 第 8 步：安装浏览器扩展

**8.1 下载**：面板 → 账号页底部「添加 / 更新账号」→ 展开「🧩 还没装扩展？」→ 点下载链接。也可以直接在地址栏访问：

```
https://你的域名/cookie-plugin-2.2.zip
```

> 从面板下载的扩展里**已经自动填好了面板地址**，不用担心填错。

**8.2 解压**到一个固定文件夹（例如 `D:\cookie插件`）。
⚠️ 解压后**不要删除、不要移动**这个文件夹，浏览器会一直读它。

**8.3 加载**：

1. Chrome 地址栏输入 `chrome://extensions`（Edge 用 `edge://extensions`）回车
2. 打开右上角的 **开发者模式**
3. 点 **加载已解压的扩展程序** → 选中第 8.2 步那个**文件夹本身**（不是里面的某个文件、更不是 zip）
4. 工具栏出现 🍪 图标就装好了

**8.4 配置**：点扩展图标 →

- **签到面板地址**：已经自动带出来了；如果是空的就手填 `https://你的域名`
- **API Key**：粘贴第 7 步复制的那串
- 点 **🔌 面板连接检查**，显示 `连接正常 ✅ API Key 有效（面板版本 2.2）` 就成了

### 第 9 步：添加第一个账号（复制 → 粘贴，两步）

以 NodeSeek 为例：

1. 浏览器打开 `www.nodeseek.com`，**手动登录**（有人机验证也没关系，你手点一下就好）
2. 停在那个网站的页面上，点扩展图标 → **📋 一键复制全部信息（含 UA）**
3. 回到面板 → 账号页「添加 / 更新账号」→ 在输入框里按 **Ctrl+V**
4. **粘上就自动完成**：面板自动认出站点 → 自动建号 → 自动填 Cookie 和 User-Agent → 立刻试跑一次 → 弹出结果分解

> **User-Agent 不用你去找。** 扩展会把浏览器真实 UA 一起带回来；万一没带，面板会自动用当前浏览器的 UA 兜底。

拉到的 Cookie 会连同 HttpOnly 的登录 Cookie 一起复制（NodeSeek 这类站点必须这样才行）。要加第二个站点就重复 1~4。

### 第 10 步：设置每天几点签到

面板 → **设置** → 「签到时间」：点时间胶囊选时/分，选时区，点保存。**改完立即生效，不用重新部署。**

- 想给某个账号单独设时间：账号列表的「签到时间」列，点胶囊设置；点「跟随全局」就回到全局时间。
- 时区默认 `Asia/Shanghai`（北京时间），下拉里可以换成别的。

### 第 11 步：绑定自定义域名（强烈建议）

`*.workers.dev` 在国内访问经常不稳定，会导致：你自己打不开面板、**扩展连不上面板**（于是所有需要本地网络的账号都被跳过）。

做法：

1. 把你的域名托管到 Cloudflare（在 Cloudflare 里加站点，改域名的 NS）
2. 控制台 → **Workers 和 Pages** → 选中你的 Worker → **设置** → **域和路由** → 添加 → **自定义域**
3. 用新域名打开面板
4. ⚠️ **去扩展弹窗里把「签到面板地址」改成新域名**，否则扩展还在连旧的 workers.dev 地址

### 第 12 步：推送通知（可选）

面板 → **设置** → 「推送通知」，任选一个填：

| 渠道 | 要填 |
|---|---|
| Telegram | Bot Token（找 @BotFather 申请）+ Chat ID（找 @userinfobot 查） |
| Bark | Bark Key（App 里那串） |
| 通用 Webhook | 一个能收 POST JSON 的地址，收到 `{title, body}` |

不填就不推送，不影响签到。勾上「启用推送」并保存即可。

## 日常使用

| 你在哪做什么 | 结果 |
|---|---|
| 账号列表 → **执行** | 立刻跑这个账号，日志里能看到网站原始回馈 |
| 账号列表 → **全部执行** | 依次跑所有启用的账号 |
| 账号列表 → **切换**（模式徽章） | 跟随默认 → 🌐 本地网络 → ☁️ 云端 循环切换 |
| 账号列表 → **启用开关** | 关掉的账号不参与定时任务 |
| 日志页 | 每次运行的时间、耗时、网站真实返回原文；可按账号/结果筛选 |

**状态徽章怎么看**：

- ✅ 已签到 / 🔴 未签到 —— **按你设置的时区**算「今天」，过了当地 00:00 会**自动全部回到「未签到」**，只有当天真的签到成功（或站点明确回「今日已签到」）才变回「已签到」；跳过和失败都不会让它变成已签到
- 网站反馈那一列，失败时下方会给一句中文「怎么办」（比如「该网站屏蔽了 CF 网络，请切本地网络」）
- ⏭️ 跳过（需要本地网络但扩展不在线；不算失败，也不会覆盖上一次的结果）
- 顶部的 **🌐 / ☁️** 表示这次用的是本地网络还是云端

**首页右上角那个「扩展在线」胶囊**：就在「退出」按钮下面。

- 🟢 **扩展在线（自动中继已启用）**：扩展正在接单，账号可以切到「本地网络」
- ⚪ **扩展离线（本地网络不可用）**：点它可立即重测一次；此状态下**不允许**把账号切到「本地网络」（面板会直接拒绝并告诉你原因，不会让你切进一个根本跑不了的模式）
- 每 30 秒自动重测一次，扩展断线/上线会自己变

## 执行模式：云端 / 本地网络

| 徽章 | 含义 | 适合 |
|---|---|---|
| ☁️ 云端 | Cloudflare 机房的 IP 直接发请求 | 普通 API 类站点（机场、Akile、天翼云盘…） |
| 🌐 本地网络 | 请求**经由你的浏览器扩展**发出，用你家的 IP + 你的登录态 | 会拦机房 IP 的站点（吾爱破解、NodeSeek、糊涂鳄…） |

几个要点：

- 账号默认跟随站点推荐的模式；扩展**在线**时，需要本地网络的账号会自动走你的网络。
- 扩展**离线**时，这些账号记为 ⏭️ 跳过，不会瞎报失败。
- 面板判断「扩展在线」的依据是：**最近 90 秒内有扩展来领过任务**。
- 扩展是常驻的：它向面板发起 15 秒的长轮询，你一点「执行」，请求通常 **1 秒内**就被扩展领走。

扩展弹窗上的按钮：

| 按钮 | 作用 |
|---|---|
| 一键发送到签到面板 | 把当前网页的 Cookie + UA 发给面板，自动打开面板并保存 |
| 一键复制全部信息（含 UA） | 复制成一段 JSON，去面板「添加/更新账号」粘贴即可 |
| ▶️ 唤醒中继（立即接单） | 让后台马上开始接单（一般不用点，扩展本来就在等） |
| 🔌 面板连接检查 | 验证面板地址和 API Key 是否正确 |

## 内置站点

| 站点 | 需要填 | 备注 |
|---|---|---|
| NodeSeek | Cookie | 登录带 Cloudflare 人机验证，无法自动登录；支持「试试手气 / 固定 5 鸡腿」开关。**建议本地网络**（云端出口没有 IPv6 会被跳提示页） |

| 糊涂鳄 | 站点地址 + Cookie | WordPress/RiPro。自动从首页发现悬浮窗用的签到接口，并在本地记忆命中的 action |
| V2EX | Cookie | 每日登录奖励，先读页面再取动态参数 |
| 看雪论坛 | Cookie | csrf_token 自动获取 |
| AkileCloud | `akile-token` | 从浏览器 localStorage 取；临近过期自动续期 |
| V2Board 机场 | 机场域名 + 邮箱 + 密码 | 表单登录后签到领流量 |
| Discuz 每日签到 | 论坛地址 + Cookie | 通用模块，适用于装 `k_misign` 插件的论坛 |
| 天翼云盘 | 189 手机号 + 密码 | 登录前自动检测是否需要验证码；需要时先在官方 App/网页登录一次（关掉设备锁） |
| 夸克网盘 | `kps` / `sign` / `vcode` | 手机抓包获取，约 2 个月过期 |
| 自定义 HTTP | URL/方法/头/体 + 判定规则 | 万能模块，支持多步录制 |

## 手动取 Cookie 的各种方式

正常情况用扩展一键复制就够了。下面这些是「不装扩展」时的备用手段，都在面板「添加 / 更新账号」→ 展开「🛠 不装扩展时的手动方式」里：

| 方式 | 怎么做 | 注意 |
|---|---|---|
| **请求头**（推荐） | F12 → 网络 → 点任一请求 → 复制请求头整段 → 粘到面板 | Cookie 和 UA 会一起提取，吾爱这种要求配对的站点最省事 |
| cURL 命令 | F12 → 网络 → 右键请求 → 复制为 cURL → 粘到面板 | 同样能带出 UA |
| 小书签 | 面板生成一段书签 → 拖到书签栏 → 在目标网站点一下 | **读不到 HttpOnly Cookie**，NodeSeek 这类不行 |
| 地址栏代码 | 面板复制代码 → 粘到手机浏览器地址栏（`javascript:` 要手打） | 同上，手机端应急用 |
| 控制台代码 | F12 → Console → 输入 `document.cookie` 回车 → 复制结果 | 同上 |
| Cookie-Editor JSON | 用 Cookie-Editor 插件导出后粘进面板 | 需要先装那个插件 |
| cookie.txt | 粘 Netscape 格式的内容 | 少数抓包工具导出的格式 |

**小贴士**

- 有些站点（吾爱破解）要求 **Cookie 与 User-Agent 配对**，UA 不一致会被 WAF 拦。用扩展或「请求头」方式就不用操心。
- Cookie 会过期。到期后日志会提示「登录已失效 / Cookie 已失效」，按第 9 步重新复制粘贴一次即可。

## 常见问题 FAQ

**Q：扩展显示「API Key 无效 / 连不上面板」，但面板里明明复制了 Key？**
A：九成是你之前给 Worker 设过 `EXTERNAL_API_KEY` 这个 Secret —— 它的优先级高于面板里生成的那串。去 Cloudflare 控制台 → 你的 Worker → **设置 → 变量和密钥**，把 `EXTERNAL_API_KEY` 删掉；或者用命令删：

```bash
npx wrangler@latest secret delete EXTERNAL_API_KEY
```

删掉后回面板重新生成一把 Key，填进扩展。

**Q：点「执行」后一直在转圈？**
A：如果这个账号是 🌐 本地网络，说明扩展没接单。检查（1）扩展是否装着并启用；（2）扩展弹窗里地址和 Key 对不对（点「面板连接检查」）；（3）`workers.dev` 在国内能不能打开，不行就绑自定义域名。
另外确认面板和扩展都是最新版：新版是「长轮询」接单（1 秒级响应），旧版要等 15~30 秒。

**Q：日志说「本地网络执行失败：中继执行超时」？**
A：扩展在你的浏览器里发这次请求超时了。常见原因是目标站有安全验证/Slider，或者那个域名没有可用的标签页。手动在浏览器打开该站点一次，确认能正常浏览，再试。

**Q：吾爱破解云端执行报 403 / reason:UrlACL？**
A：这不是 bug。吾爱破解用网宿 WAF 直接封了 Cloudflare 机房 IP。把该账号切到 **🌐 本地网络**（需要扩展在线）就能签到。

**Q：点「切换」切不到「本地网络」，提示扩展离线？**
A：这是有意拦截。没有在线扩展就没有本地网络中继，切过去只会永远等待。先按首页右上角的胶囊确认扩展在线（离线就点「面板连接检查」排查地址/Key）；扩展离线时，「切换」会在「跟随默认」和「CF 网络」之间循环，跳过本地网络这一档。

**Q：今天明明签到过了，面板却显示「未签到」？**
A：看的是**设置里那个时区**的今天。如果站点用的是别的时区，跨零点前后可能对不上；把「签到时间设置」里的时区改成该站的时区即可。另外「已签到」只认成功的运行记录，跳过/失败不算。

**Q：日志说「遇到安全验证（WAF）」？**
A：站点识别到你不是正常浏览器。用浏览器打开该站点，手动过一次验证并登录，然后重新用扩展「一键复制全部信息」更新 Cookie 和 UA。

**Q：日志说「遇到人机验证」？**
A：验证码/滑块**无法自动过**（所有签到脚本的通病）。人工在浏览器里登录一次，再重新抓一次 Cookie 即可。

**Q：执行结果一直是 ⏭️ 跳过？**
A：这个账号需要本地网络但扩展不在线（见上一条 Q）。

**Q：想加一个没有内置的网站？**
A：用「自定义 HTTP」：浏览器里人工登录并手动签到一次 → F12 → 网络 → 找到签到请求 → 右键「复制为 cURL」→ 面板粘贴导入 → 填「响应应包含」关键词 → 保存试跑。多步流程（先登录拿 token）用「多步录制」。

**Q：更新面板代码会丢账号吗？**
A：不会。更新只替换 Worker 脚本，D1 数据库是独立的；表结构变更走版本化迁移（缺列自动补，不重建表）。

**Q：D1 免费额度够吗？**
A：个人使用完全够。每分钟一次 Cron 唤醒，绝大多数只是比对时间后立即返回，不写数据库。

## 数据与安全

- **管理密码**：PBKDF2-SHA256（10 万次迭代）加盐哈希后存 D1，不存明文。
- **账号凭据**（Cookie / 密码 / token）：AES-GCM 加密后存 D1；密钥来自 `ENCRYPT_KEY` Secret，没设就在首次运行时自动生成并存进 D1。
- **会话**：服务端 session + HttpOnly + Secure + SameSite Cookie，7 天过期。
- **扩展接口**：独立的「扩展用 API Key」鉴权；服务端还支持对扩展请求做 HMAC 签名校验 + 防重放（默认不强制，兼容旧版扩展）。
- **推送密钥**：设置页读取时脱敏，更新时留空即保留旧值。
- **Cookie 传输**：扩展「一键发送」通过面板页面地址传回，面板读到后立即用 `history.replaceState` 清掉地址栏里的参数。

## 更新与备份

**更新面板**：拿到新代码后在项目目录重新部署，账号数据不受影响。

```bash
npx wrangler@latest deploy
```

> 如果这次更新包含扩展改动，部署完**再去面板下载一次扩展并重新加载**（面板里内嵌的是扩展源码，必须重新下载才会更新）。

**备份数据库**（建议偶尔做一次）：

```bash
npx wrangler@latest d1 export daily-checkin-panel --remote --output backup.sql
```

> 备份文件里是**加密后**的凭据。如果 `ENCRYPT_KEY` 是自动生成的，恢复时请用同一个 D1，否则解不开。
> 想随时查看账号列表：`npx wrangler@latest d1 execute daily-checkin-panel --remote --command "SELECT id,name,site FROM accounts"`

## 项目结构 / 自己加站点

```
daily-checkin-panel/
├── wrangler.toml          # Worker 配置、Cron、D1 绑定（要改 database_id）
├── src/
│   ├── index.js           # 路由 + API + Cron 入口
│   ├── runner.js          # 执行引擎（遍历账号 / 写日志 / 推送）
│   ├── db.js              # 表结构 + 版本化迁移
│   ├── crypto.js          # 密码哈希 / 凭据加解密
│   ├── schedule.js        # 签到时间与时区判定
│   ├── notify.js          # Telegram / Bark / Webhook
│   ├── probe.js           # 签到接口自动探测
│   ├── ext-zip.js         # 动态生成扩展 zip（注入面板地址）
│   ├── ext-files.js       # 自动生成：扩展源码内嵌（别手改）
│   ├── lib/
│   │   ├── web.js         # 模拟浏览器的请求工具（UA/Referer/表单）
│   │   ├── relay.js       # 本地网络中继（Worker 侧）
│   │   ├── signals.js     # 统一网站反馈识别（成功/已签/登录/验证码/WAF）
│   │   └── ext-auth.js    # 扩展请求鉴权（API Key + 签名 + 防重放）
│   └── sites/             # 各站点签到模块 + index.js 注册表
├── public/
│   ├── index.html         # 管理后台 SPA
│   └── ext-src/           # 扩展源文件（改完需重新生成 ext-files.js）
├── tools/
│   ├── gen-ext-files.mjs  # 把 public/ext-src/ 打包进 src/ext-files.js
│   ├── gen-tp-preview.mjs # 生成时间选择器预览页
│   ├── gen-ui-preview.mjs # 生成卡片排版预览页
│   └── check-html.mjs     # 标签配对检查
└── test/                  # 零依赖单测：node test/xxx.test.mjs
```

**自己加一个站点**：

1. 在 `src/sites/` 新建文件（照着 `nodeseek.js` 抄最省事）：

```js
export const mysite = {
  id: 'mysite',
  name: '我的站点',
  desc: '一句话说明',
  fields: [{ key: 'cookie', label: 'Cookie', type: 'textarea', required: true }],
  tips: '给用户的提示',
  async run(creds, ctx) {
    // ctx: { env, db, account, meta }；meta 可读写并会自动持久化
    return { ok: true, message: '签到成功' };
  },
};
```

2. 在 `src/sites/index.js` 的 `SITES` 里注册。
3. 重新部署，网页表单会自动出现这个站点。

**改扩展**：改 `public/ext-src/` 下的文件 → 跑 `node tools/gen-ext-files.mjs` 重新生成 `src/ext-files.js` → 部署。**否则用户下载到的还是旧版扩展。**
