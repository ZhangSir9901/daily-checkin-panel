# 陌生站点适配成功率说明

> 用扩展抓 Cookie 的方式，给一个没见过的网站做签到适配，大概有多大把握？
> 下面是按签到接口形态分的五档估计。签到场景里 80% 的网站落在前两档。

## 五档成功率

| 档位 | 站点形态 | 举例 | 成功率 |
|---|---|---|---|
| 1 | **纯 Cookie 签到**：签到 = 带 Cookie 请求一个 URL | WordPress、Discuz、Typecho 类论坛博客 | **~90%** |
| 2 | **Cookie + 简单校验**：要 UA 配对、Referer，或从页面提一个 token（formhash 之类） | 吾爱破解（WAF 验 UA） | **~60–70%** |
| 3 | **多步流程**：先调接口拿 token 再签到 | 登录态续期后签到的站 | **~40–50%** |
| 4 | **反爬 / 人机验证**：Cloudflare 挑战、滑块、行为验证 | 部分机场、薅羊毛重灾区 | **~15–25%** |
| 5 | **强风控**：设备指纹 + 行为分析 | 银行、支付级 | **接近 0（不建议碰）** |

**综合**：社区成员照教程自己动手，综合成功率约 **60–70%**；
只算"录个 URL 就完事"的第 1 档，**90%+**。

## 为什么 Cookie 方案起点高

最难的一步是"拿到可用的登录态"。扩展用 `chrome.cookies` 直接读浏览器存的 Cookie，
连 HttpOnly 的都能拿到，不受 JS 限制——这一步解决了，后面只是"把请求原样重放"。

## 提高成功率的办法

1. **先录制再调**：在网站上亲手点一次签到，用扩展「🎬 录制签到请求」（2.19+）把那次请求的
   method / URL / 请求头 / 请求体抓下来，面板会自动打开预填好的添加账号表单 ——
   原样重放成功率最高，连 F12 都不用开。
2. **从 cURL 填入**：浏览器 F12 → 网络面板 → 对签到请求"复制为 cURL" →
   面板自定义 HTTP 里"从 cURL 填入"，Cookie 会自动换成 `{{cookie}}` 占位符。
3. **403 / 验证页**：多半是机房 IP 被拦，把账号执行模式切到"中继"或"浏览器"
   （走你自己本地网络），成功率能回来一大截。
4. **401 / 跳登录页**：Cookie 过期了，扩展重新抓一次就行。
5. **录好的配置可以分享**：调通后在"🌍 社区站点"卡片导出配置，
   别人导入填自己的 Cookie 就能用，不用重复踩坑。详见 `CONTRIBUTING.md`。

## 免责

- 只适配自己有账号、允许自动签到的网站；有明确禁止脚本条款的站请遵守站规。
- 第 4–5 档的站点今天能用、明天可能就失效，属正常现象。
